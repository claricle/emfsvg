= Compatibility with libemf2svg

`emfsvg` converts EMF and SVG using the `emf` domain model. The parity
acceptance contract is exact bytes against committed artifacts. Lossy SVG
comparisons remain useful diagnostics, but cannot establish byte parity.

== Reproduce the checks

Follow link:../spec/fixtures/README.adoc[fixture setup] to materialize the
external corpus and set `EMF_FIXTURE_ROOT`. The manifest pins corpus revision
`a549346e4c4cacf9da6c86ab451a9f8401fa9672`, 208 accepted EMF inputs,
21 corrupted inputs, and 416 SVG artifacts. The shared resolver validates the
revision, exact inventories, and hashes before comparisons are collected.
Missing roots, unexpected or missing files, and changed bytes fail setup.
There are no developer-machine or sibling-checkout defaults.

The runtime is independent of that corpus checkout. Development temporarily
pins `emf` to Git revision `6ed27136394d13d7e065c93d0a802439d4586df4`.
A containing released package, native backend selection, and upstream resource
and diagnostic contracts remain qualification requirements. A valid corpus
inventory does not establish runtime qualification.

[source,bash]
----
bundle exec rspec spec/parity_manifest_spec.rb spec/parity_corpus_spec.rb
bundle exec rspec spec/golden_spec.rb spec/round_trip_golden_spec.rb spec/compat_with_libemf2svg_spec.rb --dry-run
----

Collection verifies the contract's size, not its outcome. Once setup is valid,
run a selected real comparison, for example:

[source,bash]
----
bundle exec rspec spec/round_trip_golden_spec.rb --example image1
bundle exec rspec spec/compat_with_libemf2svg_spec.rb --example image1
----

== Conversion resource guards

`Emfsvg.from_bytes` checks the input byte count against
`Emf::Emr::Parser::MAX_INPUT_BYTES` before parsing. `Emfsvg.from_file` checks
file size before reading and checks the resulting bytes again. Inputs exactly
at the ceiling remain accepted. Missing files retain their filesystem error.

The SVG builder checks each append against
`Emfsvg::Renderer::MAX_OUTPUT_BYTES` (500 MiB), including newlines and tags. It
checks the expanded size of escaped text and attributes before allocating the
escaped copy. Exceeding either byte ceiling raises `Emfsvg::ResourceLimitError`,
a subclass of `Emfsvg::Error`, with `resource` (`:input_bytes` or `:output_bytes`),
`limit`, and `actual` readers. These local checks do not wrap an upstream failure,
so they have no original exception cause. They do not set process RSS or virtual
address-space ceilings.

Before path analysis, the renderer limits accepted models to
`Emfsvg::Renderer::MAX_RECORDS` (1,000,000) enumerated records. This is an
`emfsvg` safety policy, independent of upstream parser limits. It also applies to
caller-provided models and lazy enumerables: collection stops at the first
excess record, without trusting the header's declared count, and raises
`Emfsvg::ResourceLimitError` with `resource: :records`, the configured `limit`,
and the observed `actual` count (limit plus one). Exactly the ceiling is accepted.

The renderer rejects nonfinite header coordinates and nonpositive or nonfinite
header/output dimensions with `Emfsvg::RenderError` before creating its builder.
These checks and the output ceiling provide focused allocation protection;
they do not bound every intermediate renderer allocation. Sparse GDI object
handles no longer allocate an array through the numeric handle value. The frozen
21-input corrupted-corpus observation at `c88ffe1` completed with 18 SVG outputs
and three typed parse errors, no unexpected exceptions or resource breaches, and
646 protected files unchanged. Peak RSS was 105440 KiB and maximum elapsed time
was 1.396689 seconds under supplied 30-second/512-MiB ceilings. This observation
used the earlier runtime pin; cross-backend qualification and a calibrated
baseline remain pending.

Unreadable input currently raises `Emfsvg::ParseError` with its original upstream
format/parse exception as `cause`; unexpected backend failures propagate. The
remaining corrupted-input acceptance contract must distinguish recoverable
malformed records (SVG plus the exact structured skipped-record warnings) from
unreadable containers (typed parse failure with its cause and no partial SVG).
It must also establish typed upstream resource failures with their metadata and
causes. Qualification of those outcomes across Ruby, native, and auto actually
selecting native remains blocked on released upstream diagnostics/resources and
the public conformance adapter. Warning fields and native-selection reporting
must follow those landed interfaces rather than an inferred contract.

== Resource calibration command

`scripts/calibrate_resource_limits.rb` prepares generation and verification of a
versioned resource baseline. It currently refuses before corpus execution:
upstream https://github.com/claricle/emf/issues/65[emf #65] and
https://github.com/claricle/emf/issues/66[emf #66] have no pinned landed revisions,
the released runtime/package and native artifact are unqualified, and the public
calibration adapter is not yet qualified. Filling manifest fields alone cannot qualify
the loaded implementation. There is no generated corpus baseline.

The adapter must verify the exact manifest-selected corpus, independently loaded
released runtime and package digest, native artifact/ABI, and public conversion
outcomes. Ruby, native, and native-selected auto production conformance is a
prerequisite; environment variables alone do not prove the selected backend.
The existing command reuses `scripts/check_parity_provenance.rb` metadata checks
and requires the two exact upstream issue identities. Its executable sampling,
schema, derivation, drift, and atomic-write behavior has focused synthetic tests.
A production adapter core now exercises public conversion in a fresh process,
checks exact SVG bytes and warnings, preserves typed exceptions and causes,
and rejects input/runtime/artifact drift or backend fallback. Its native-selected
auto observation uses the pinned upstream private selector and explicitly does
not establish a public backend contract. Startup stderr remains visible and
causes rejection. This core does not bypass prerequisite checks; released-package
and public-contract qualification are required before corpus calibration.

`spec/corrupted_resilience_spec.rb` prepares the corpus caller behind that same
prerequisite gate. It requires exact manifest source paths, hashes and reviewed
outcomes for every corrupt input, checks the stored baseline ceilings, and
verifies that the baseline and forbidden-reference sentinel remain unchanged.
Its synthetic mechanics tests do not qualify the corpus. The real corpus example
reports the missing qualification explicitly; it cannot turn unresolved manifest
outcomes into observed expectations or generate a baseline.

The following is the intended invocation once those gates are satisfied. Set all
three outer caps explicitly for the host; there are no default caps. Values must
be finite and positive, and remain below the host's own safety limits. The output
directory must already exist.

[source,bash]
----
bundle exec ruby scripts/calibrate_resource_limits.rb generate \
  --manifest spec/fixtures/parity_manifest.yml \
  --fixture-root "$EMF_FIXTURE_ROOT" \
  --outer-rss-cap-mib "$EMFSVG_CALIBRATION_RSS_CAP_MIB" \
  --outer-as-cap-mib "$EMFSVG_CALIBRATION_AS_CAP_MIB" \
  --timeout-seconds "$EMFSVG_CALIBRATION_TIMEOUT_SECONDS" \
  --output spec/fixtures/resource_limits/emfsvg-v1.yml

bundle exec ruby scripts/calibrate_resource_limits.rb check \
  --manifest spec/fixtures/parity_manifest.yml \
  --fixture-root "$EMF_FIXTURE_ROOT" \
  --outer-rss-cap-mib "$EMFSVG_CALIBRATION_RSS_CAP_MIB" \
  --outer-as-cap-mib "$EMFSVG_CALIBRATION_AS_CAP_MIB" \
  --timeout-seconds "$EMFSVG_CALIBRATION_TIMEOUT_SECONDS" \
  --baseline spec/fixtures/resource_limits/emfsvg-v1.yml
----

Each selected input has three sequential fresh-child repetitions through
`spec/support/bounded_conversion.rb`. Authoritative calibration requires Linux,
`/proc` RSS/virtual-size measurements, child `RLIMIT_AS`, and parent monotonic-time
and RSS watchdogs with process-group cleanup. The recorded TERM grace is 0.2
seconds. RSS and address space are distinct measurements; `RLIMIT_AS` limits
virtual address space. macOS has diagnostic RSS/time support but cannot produce
an authoritative baseline because address-space enforcement is unavailable.
Unsupported platforms and unavailable enforcement fail closed. Linux enforcement
still needs real-host qualification; its implementation is not that evidence.

Schema version 1 records `provenance`, `inputs`, `outer_caps`, `grace_seconds`,
`repetitions`, `samples`, and `derived_limits`. Provenance pins the manifest digest,
`emfsvg` revision, released runtime version/package/source, native artifact/source/
ABI, actual native selection, OS/architecture/Ruby, and enforcement mechanisms.
Each input records its name, SHA-256 and expected outcome. Each sample records
case/repetition, input/output bytes, warnings, exception, elapsed seconds, peak RSS
and address space in KiB, exit status, signal, safety verdict, and mechanism.
Missing fields, changed coverage/order, unsafe outcomes, or input/provenance drift
reject the run.

`generate` derives global ceilings from the maxima of all stored samples: wall
seconds are rounded up from four times elapsed time; RSS MiB from twice peak RSS
plus 64 MiB; address-space MiB from twice peak address space plus 128 MiB. A
derived ceiling reaching an explicit outer cap rejects generation. Valid output
is written to a temporary file in the destination directory, flushed and synced,
then renamed over the destination; validation or serialization failure preserves
the prior baseline.

`check` validates the stored schema, sample completeness and stored derivations
before running children under the stored derived ceilings. Fresh inputs,
provenance, repetition count, mechanisms and conversion outcomes must match.
Fresh elapsed/RSS/address-space values may vary, must stay within those stored
ceilings, and are reported as observed samples. Checking neither compares timings
byte for byte nor changes the baseline, adds tolerance, or recalibrates it.

To add a corrupted-input regression, pin its corpus revision and bytes, give it an
explicit recoverable/unreadable/resource outcome and exact warning expectation,
and exercise the public conversion through the bounded helper. Do not remove an
input, weaken warning assertions, or widen a resource budget to make a failure
pass. Cases requiring unavailable upstream diagnostics or native conformance
remain explicit blockers. A replacement resource baseline requires a fresh,
qualified generation run and review of its provenance and raw samples.

== Explicit live C diagnostics

`Emfsvg::Compat` in `spec/support/emfsvg_compat.rb` is the sole live C resolver.
Set both variables explicitly; the wrapper and library directory must exist:

[source,bash]
----
export EMF2SVG_REF_PATH=/absolute/path/to/emf2svg_ref
export EMF2SVG_REF_LIB_DIR=/absolute/path/to/library-directory
bundle exec ruby scripts/run_compat_check.rb
bundle exec ruby scripts/run_emf_svg_compare.rb
EMFSVG_LIVE_REFERENCE=1 bundle exec rspec spec/fidelity_regression_spec.rb
----

These tools require the verified corpus as well. Missing setup and failed C
conversions fail with an error. The fidelity spec is excluded unless explicitly
enabled with `EMFSVG_LIVE_REFERENCE=1`. Diagnostic byte ratios, element overlap,
and lossy matcher results are separate from the strict acceptance contracts.

== Guarded baseline regeneration

[source,bash]
----
bundle exec ruby scripts/regenerate_golden.rb --check
# Only after verifying reference provenance and intentionally accepting drift:
bundle exec ruby scripts/regenerate_golden.rb --write
----

Both modes validate the corpus and explicit C tooling and stage both baseline
sets. `--check` reports differences without changing committed artifacts.
`--write` requires verified C status, an exact source revision, a build recipe,
and an executable checksum matching the configured wrapper. It updates both
artifact sets and manifest digests with a cooperative writer lock and rollback
on ordinary failures. Concurrent-reader atomicity and crash recovery are not
provided. Review the entire fixture diff before committing; see
link:../spec/fixtures/README.adoc[the full procedure].
