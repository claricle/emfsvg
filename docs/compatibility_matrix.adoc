= Compatibility with libemf2svg

`emfsvg` is a clean-room rewrite that handles a subset of EMF records.
This document tracks the gap against `libemf2svg` (the GPLv2 C library
we replace).

== How to measure

Run the compat check after building `libemf2svg`:

    cd ../libemf2svg
    cmake -S . -B build -DLONLY=ON
    make -C build
    cc -I inc -L build -lemf2svg emf2svg_ref.c -o emf2svg_ref

    cd ../emfsvg
    bundle exec ruby scripts/run_compat_check.rb

This walks every EMF fixture, generates both SVG outputs, and prints
a per-fixture + aggregate comparison.

== What "compatibility" means here

We do NOT assert byte-identical output. libemf2svg:

* emits different whitespace and attribute ordering,
* wraps primitives in `<g transform="translate(...)">` shells,
* includes a SVG DTD doctype,
* renders text via embedded `<text>` elements with iconv'd strings,
* decodes DIB bitmaps to base64 PNG.

Reproducing all of that exactly is not the goal. The goal is
**visual and structural equivalence** for the records `emfsvg`
handles, plus a documented superset gap for the records it doesn't.

== Current state (as of 2026-07-24)

Aggregate across all 208 fixtures in `spec/fixtures/`:

[cols="1,4"]
|===
| Total fixtures       | 208
| libemf2svg output    | ~59 MB
| emfsvg output        | ~25 MB
| Byte ratio           | 43.2%
| Avg element overlap  | ~50%
|===

The ratio varies wildly per fixture:

* **0-5%**: fixtures dominated by records `emfsvg` doesn't render yet
  (text, bitmaps, EMF+ drawing records, region operations).
* **20-50%**: typical mixed-content fixtures.
* **60-80%**: fixtures whose records `emfsvg` does handle.

== Records emfsvg handles (visit_* methods in EmrVisitor)

* Primitives: Rectangle, Ellipse, RoundRect, LineTo, MoveToEx,
  Polygon/Polyline + 16-bit variants
* Paths: BeginPath/EndPath/CloseFigure/FillPath/StrokePath/
  StrokeAndFillPath/AbortPath
* State: SetTextColor, SetBkColor, SetBkMode, SetMapMode, SetRop2,
  SetPolyFillMode, SetTextAlign, SetStretchBltMode
* Transforms: SetWorldTransform, ModifyWorldTransform
* Objects: CreatePen, CreateBrushIndirect, SelectObject, DeleteObject,
  SaveDc, RestoreDc
* Misc: SetMiterLimit, SetWindow/Viewport Org/Ext

== Records emfsvg does NOT handle yet

* Text: ExtTextOutA/W, PolyTextOutA/W (needs UTF-16 + glyph handling)
* Bitmaps: BitBlt, StretchBlt, StretchDIBits, AlphaBlend, TransparentBlt,
  MaskBlt, PlgBlt (needs DIB decoding)
* Arc family: Arc, ArcTo, Chord, Pie (parametric path reconstruction)
* Beziers: PolyBezier, PolyBezierTo + 16-bit variants
* Clipping: IntersectClipRect, ExtSelectClipRgn, SelectClipPath
* PolyPolygon / PolyPolyline (multi-subpath)
* Region ops: FillRgn, FrameRgn, InvertRgn, PaintRgn
* Gradients: GradientFill
* EMF+ drawing records types (separate format; emf parses them but
  emfsvg does not yet render them)

== Spec coverage

`spec/compat_with_libemf2svg_spec.rb` auto-skips if `libemf2svg`'s
binary is not available. It:

1. For every fixture: asserts both emfsvg and libemf2svg produce
   well-formed XML.
2. For a sample: asserts emfsvg emits only element types that also
   appear in libemf2svg's output (no foreign tags).
3. Regression floor: emfsvg's total byte output for the simple
   fixtures is >= 30% of libemf2svg's. Tighten as handlers are added.

== Path forward

Each new record handler in `EmrVisitor` should:

1. Be added to the `HANDLERS` hash.
2. Add a per-record spec in `spec/per_record/`.
3. Move the corresponding fixture from the "0-5%" bucket to a higher
   bucket in the compat matrix.
4. Optionally bump the regression floor in the compat spec.

The compat matrix is regenerated by CI on every PR (when the libemf2svg
binary is available) so regressions are caught immediately.
