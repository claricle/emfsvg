# Contributing to emfsvg

== Branches and PRs

* Never commit to `main`. Create a feature branch
  (`feat/...`, `fix/...`, `docs/...`) and open a PR.
* Never push tags yourself. Tags are releases; the maintainer decides.
* Squash-merge or rebase-merge is preferred; the maintainer chooses per
  PR.

== Code style

* `bundle exec rubocop` must pass clean.
* `bundle exec rspec` must pass with no failures.
* Target Ruby 3.1+. Use pattern matching, endless ranges, and
  frozen-string-literals.

== Constraints (project-specific)

These are absolute. PRs that violate them will be rejected.

* **No `require_relative`** in `lib/`. No `require` of internal paths.
  Use Ruby `autoload` declared in the immediate parent namespace's file.
* **No `double()` in specs.** Use real instances or `Struct.new` for
  plain data.
* **No `send` to private methods**, no `instance_variable_set`/`get`,
  no `respond_to?` for type checks.
* **No AI attribution** in any commit message, PR description, code
  comment, or changelog entry.
* **Never delete source files** unless the user explicitly approves.

== Adding a new EMF record handler

In `lib/emfsvg/visitors/emr_visitor.rb`:

1. Add the wire class to the `HANDLERS` hash:
   `Emf::Emr::Binary::Records::Foo => :visit_foo`
2. Add the handler method:
   ```ruby
   def visit_foo(wire)
     # emit SVG via @builder.tag/...
   end
   ```
3. Add a spec in `spec/emfsvg/` exercising the new handler against a
   fixture or a synthetic Emf::Model::Metafile.

== Adding tests

* The renderer walks `Emf::Model::Metafile` directly. Use
  `Emf.parse_file(...)` to construct test inputs.
* The visitor and DeviceContext are exercised in isolation in
  `state_spec.rb`.
* The CLI is exercised via `Open3` in `cli_spec.rb`.

== Running tests

  bundle exec rspec                       # full suite
  bundle exec rspec spec/svg_builder_spec.rb
  bundle exec rspec -e "converts EMF to SVG"     # by description

The full suite (27 examples) runs in under 0.1 seconds.

== Ribose Contributor License Agreement

Before your first pull request can be merged in any Ribose GitHub
organization, you need to be covered by the Ribose Contributor License
Agreement (CLA). Sign once; one signature covers every Ribose
organization.

* *Individual contributors*: sign the Individual CLA at
  https://cla.ribose.com/icla[cla.ribose.com/icla]. The `cla/ribose`
  check on your pull request reports the state, and you can also sign
  from the pull request by commenting `@ribose-cla agree` and completing
  the one-click link the App replies with.
* *Corporate contributors*: if your employer has an executed
  Organization CLA, the employer's Point of Contact adds your GitHub
  handle to its Schedule A at
  https://cla.ribose.com/organizations[cla.ribose.com/organizations], or
  you can request coverage there yourself. No individual signature is
  then needed.
* *The full guide*: the signing flows and the agreement text are at
  https://github.com/riboseinc/cla/blob/main/docs/SIGNING.md[the Ribose
  CLA signing guide].
