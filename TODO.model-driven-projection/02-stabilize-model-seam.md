# 02 — Define the model-projection contract

## Context

The production path already calls `Emf.parse` and passes an `Emf::Model::Metafile` into `Emfsvg::Renderer` and `EmrVisitor`; that Ruby façade, including `record.wire`, is the fixed boundary for issue #23. The published [claricle/emf#15](https://github.com/claricle/emf/issues/15) proposes an internal native-parser swap while preserving the public model and Ruby fallback. Its acceptance covers model parity on named fixtures, corrupt-input parsing without a crash within 60 seconds, round-trip compatibility, and a performance target. It does not promise record limits, structured diagnostics, typed resource failures, native status mapping, or a release, so none of those may be assigned to #15 or counted as issue #23 implementation.

The currently inspected model exposes only `Metafile#errors`; its entries do not identify record index or disposition, and the collection can describe both dropped records and records preserved as `Raw`. `emfsvg` does not consume that collection and has no conversion-level warning channel. The runtime dependency is also distinct from the corpus checkout: `emfsvg.gemspec` permits `emf ~> 0.1`, `Gemfile.lock` resolves `emf 0.1.2`, and changing `EMF_FIXTURE_ROOT` cannot change the code Bundler loads.

## Work

- Treat #15 as an external gate. Record its exact landed commit and verify the issue's published acceptance through the public `Emf.parse` → `Emf::Model`/`record.wire` boundary. Do not infer resource, diagnostic, backend-error, or packaging guarantees from the issue. A linked PR and containing revision are still evidence gaps and must be recorded when available.
- Inspect the landed #15 revision before integration. If it does not already satisfy either contract below, open a separate `claricle/emf` issue for that contract, record its public URL and landed revision in proposed `spec/fixtures/parity_manifest.yml`, and block cards 02 and 04 on its conformance evidence. The upstream implementation, review, release work, and effort remain outside this plan.
- Define the proposed upstream diagnostic consumer contract as `Emf::Model::Metafile#diagnostics`, returning ordered immutable `Emf::Model::Diagnostic` values with `record_index`, `record_code`, `record_type`, `byte_offset`, and `disposition`. `record_index` is the zero-based ordinal in the physical record stream; `record_code` and `byte_offset` are integers; `record_type` is the canonical EMR name, using `UNKNOWN(0xNNNNNNNN)` when no name exists; and `disposition` is exactly `:skipped` or `:preserved_raw`. Ruby, native, and native-selected `auto` must return identical values for the same bytes. Existing `Metafile#errors` may remain for compatibility, but `emfsvg` must not infer disposition from its text or from the presence of a `Raw` record.
- Require a proposed upstream `spec/emf/diagnostic_contract_spec.rb`, owned by the separate upstream issue, to exercise a pinned fixture containing both a skipped malformed record and a preserved-as-`Raw` record under `EMF_BACKEND=ruby`, `native`, and native-selected `auto`. It must compare the complete diagnostic arrays, including index/code/type/offset/disposition, and prove that valid unknown `Raw` records are not reported as skipped.
- Define the separate upstream resource consumer contract observationally: any parser-enforced resource refusal is the public `Emf::ResourceLimitError` under `ruby`, `native`, and native-selected `auto`, with stable `resource`, `limit`, and `actual` metadata and no backend-specific exception or panic. A proposed upstream `spec/emf/resource_limit_contract_spec.rb`, owned by that separate issue, supplies identical accepted and rejected inputs to all three modes and proves the selected backend. This plan does not prescribe the guard algorithm, threshold, native status table, or internal file changes.
- Pin runtime code separately from corpus data. For pre-release integration only, add an exact Git source and full commit SHA in `Gemfile` and refresh `Gemfile.lock` so its `GIT` section records that revision; proposed `spec/runtime_dependency_spec.rb` compares it with `git -C "$(bundle info --path emf)" rev-parse HEAD`. For final qualification, wait for a release containing the same prerequisite revision, replace `spec.add_dependency "emf", "~> 0.1"` in `emfsvg.gemspec` with that literal minimum plus the existing `< 0.2` ceiling (or the next incompatible ceiling if the release series changes), remove the Git override, refresh `Gemfile.lock`, and record the package version/checksum-to-source-revision mapping. The external corpus revision never satisfies this runtime check.
- Add proposed `spec/model_projection_spec.rb` as the focused contract for `Emfsvg.from_bytes`, `Emfsvg.from_file`, and `Emfsvg.to_svg`, covering the model object, ordered records, typed payloads, preserved `Raw` records, diagnostic-bearing records, and fatal parse failures used by the renderer. Keep any adaptation to the final upstream façade in one boundary helper rather than spreading version checks through `Renderer` or `EmrVisitor`.
- Preserve the SVG `String` return from `from_bytes`, `from_file`, and `to_svg`. At the shared projection boundary, select only diagnostics whose disposition is `:skipped` and emit exactly one `Kernel.warn` line to stderr per conversion, in ascending `record_index`: `emfsvg: skipped EMF records: index=<n>,type=<name>,code=<n>,offset=<n>;...`. A clean model and a model containing only `:preserved_raw` diagnostics emit no skipped-record warning. The warning is independent of existing opt-in visitor verbosity, and nested public calls must not duplicate it.
- Add `Emfsvg::ResourceLimitError < Emfsvg::Error` to `lib/emfsvg/error.rb`, with immutable `resource`, `limit`, and `actual` readers. Update `lib/emfsvg.rb` so the error file is loaded before the public conversion boundary and map an upstream resource failure to this class with the same metadata and the original exception as `cause`. Extend `spec/emfsvg_spec.rb` to prove the public constant, hierarchy, metadata, and cause; do not map unreadable input or generic backend failures to it.
- Translate only unreadable input, including input without a valid EMF header, into `Emfsvg::ParseError`. Add proposed `spec/corrupted_resilience_spec.rb` examples that assert the exact warning line for a skipped record and no such warning for a preserved-`Raw` record, in addition to the per-corpus cases in card 04.
- Add proposed `spec/runtime_isolation_spec.rb` whose fresh subprocesses perform a successful conversion, an unreadable-input conversion, and a resource-limit conversion while `EMF2SVG_REF_PATH` and `EMF2SVG_REF_LIB_DIR` point to a forbidden sentinel. Require the expected output/error contract, no sentinel invocation, and no libemf2svg or compatibility-helper entry in `$LOADED_FEATURES`; inspect loaded shared libraries through `/proc/self/maps` on Linux or `/usr/bin/vmmap` on macOS when available. Card 05 separately inspects the built gem's files and runtime dependencies.
- Reconcile PR #24's record-name cache with these contract specs so its `record.wire` optimization remains valid after the dependency pin changes.

## Done when

- The exact landed #15 revision is recorded and satisfies only its published model/parser acceptance; any additional diagnostic or resource contract has its own upstream issue URL, conformance evidence, and landed revision.
- The pinned upstream runtime exposes complete index/code/type/offset/disposition diagnostics with identical results under `ruby`, `native`, and native-selected `auto`, and the conformance fixture distinguishes `:skipped` from `:preserved_raw` and valid unknown `Raw` records.
- The pinned upstream runtime exposes the same typed resource failure and metadata under all three backend selections, with the actual selected backend proven and no fallback masking.
- `emfsvg.gemspec` and `Gemfile.lock` resolve the released package containing the recorded prerequisite revision; the runtime dependency spec proves the loaded version/source mapping independently of `EMF_FIXTURE_ROOT`, and any temporary Git override is absent from final qualification.
- Production conversion uses `Emf.parse`, `Emf::Model`, and `record.wire` without a direct Rust binding or libemf2svg runtime load.
- Recoverable skipped records yield SVG plus the exact one-line warning, while clean and preserved-`Raw`-only models emit no skipped-record warning.
- `Emfsvg::ResourceLimitError` is publicly loaded, retains `resource`, `limit`, and `actual`, and preserves the upstream exception as its cause; only unreadable input raises `Emfsvg::ParseError`.
- Fresh subprocesses prove successful conversion, unreadable-input handling, and resource-limit handling while the legacy C resolver is forbidden; the sentinel is untouched and unsupported shared-library inspection is reported rather than represented as a pass.
- PR #24's renderer optimization satisfies the pinned façade without changing exact output.

```sh
(cd "$EMF_RUNTIME_SOURCE" && EMF_BACKEND=auto EMF_NATIVE_LIBRARY="$EMF_NATIVE_LIBRARY" bundle exec rspec spec/emf/diagnostic_contract_spec.rb spec/emf/resource_limit_contract_spec.rb)

```
