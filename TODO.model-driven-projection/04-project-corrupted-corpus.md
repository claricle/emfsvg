# 04 — Project the corrupted corpus safely

## Context

Twenty-one corrupted EMF inputs are visible in the current external corpus, but no `emfsvg` spec drives them through parse and projection. Prior unbounded runs consumed approximately 15–17 GB, so parser diagnostics alone do not establish safety. The inspected upstream parser has some input and variable-array checks but no contract that supplies the typed, cross-backend resource failure or record disposition required here. Card 02 therefore gates this work on a pinned runtime revision that has landed #15 and separately satisfies the structured-diagnostic and typed-resource consumer contracts; those contracts must not be attributed to #15 unless its landed code actually contains them. `Emfsvg.from_file` in `lib/emfsvg.rb` uses `File.binread` before a local input-size check. On the renderer side, `Renderer::MAX_OUTPUT_BYTES` in `lib/emfsvg/renderer.rb` is checked only after `SvgBuilder` has materialized output, and `Renderer#visit_records` copies the record set with `to_a`. `Emfsvg::DibDecoder` has no production renderer or CLI call site, so standalone decoder hardening cannot establish this card's corrupted-corpus acceptance criterion and is excluded.

## Work

- Inventory every corrupted fixture in proposed `spec/fixtures/parity_manifest.yml` with its expected class: recoverable with an exact skipped-record list, or unreadable with the reason no valid model can be formed.
- Before calibration, run proposed `spec/runtime_dependency_spec.rb` and verify that Bundler loaded the Card 02 pinned `emf` runtime, not the corpus checkout. Require the manifest's #15 revision, separate upstream diagnostic/resource issue URLs and landed revisions when needed, runtime version or Git SHA, and passing `ruby`/`native`/native-selected-`auto` conformance evidence; refuse any other combination. Final qualification requires the containing released package.
- Add proposed `spec/corrupted_resilience_spec.rb` to drive every case through public `Emfsvg.from_bytes` behavior and validate SVG, warning, or `Emfsvg::ParseError` as applicable.
- Add proposed `spec/resource_limits_spec.rb` to inventory the actual guards and public failures at the pinned upstream revision rather than assuming a symbol or algorithm not promised by #15. Also inventory downstream `Emfsvg::Renderer::MAX_OUTPUT_BYTES` and the absence of an image-dimension limit. Name and probe the allocations that can precede enforcement: `File.binread`, upstream model construction, `@metafile.to_a`, dimension-dependent renderer work, and complete `SvgBuilder` materialization.
- Add emfsvg-owned pre-allocation checks at the narrowest public or owning boundary: `File.size` before `File.binread` and `bytes.bytesize` before `Emf.parse`; a record bound before `@metafile.to_a` for caller-supplied models; finite, positive header/output dimensions before renderer work; and an incremental `SvgBuilder` byte budget before appends rather than only after `to_s`. Use overflow-safe division/comparison rather than computing attacker-controlled products first.
- Add proposed `spec/support/bounded_conversion.rb` to execute one manifest fixture per child process group and proposed `scripts/calibrate_resource_limits.rb` with `generate` and `check` modes. Add proposed versioned baseline `spec/fixtures/resource_limits/emfsvg-v1.yml`. Generation runs every manifest-selected valid control and corrupt case sequentially, three repetitions each, with explicit `--outer-rss-cap-mib`, `--outer-as-cap-mib`, and `--timeout-seconds` values below the host's machine guard; there are no implicit safety defaults.
- Give the baseline schema a version and record the manifest digest, every input digest and expected outcome, `emfsvg` revision, loaded `emf` version/package checksum/containing source revision, selected backend, native artifact provenance, OS/architecture/Ruby, enforcement capabilities, supplied outer caps, repetition count, and each child's input/output bytes, warnings, exception, elapsed time, peak RSS, peak virtual address space, exit status, and signal. Record the derived wall, RSS, and address-space ceilings separately. `generate` writes atomically and prints the baseline path, case/repetition counts, zero unsafe outcomes, and all three derived ceilings; `check` reruns the same pinned inputs without modifying the artifact and fails on provenance, schema, sample, or derivation drift.
- Derive rather than guess the three committed ceilings: wall time is four times the slowest successful monotonic elapsed time; RSS is twice the highest successful peak RSS plus 64 MiB; address space is twice the highest successful peak virtual address space plus 128 MiB. Round each upward to the next whole unit recorded by the schema. Refuse to generate a baseline if a measurement is unavailable on the authoritative platform, a derived ceiling reaches its separately supplied outer cap, or any case terminates unsafely.
- On Linux CI, create each child with `pgroup: true`, set only the child's `Process::RLIMIT_AS` to the baseline address-space ceiling, and sample `/proc/<pid>/status`: `VmRSS`/`VmHWM` provide RSS evidence while `VmSize`/`VmPeak` provide virtual-address-space evidence. The parent independently enforces the RSS and monotonic wall ceilings; on either breach it sends TERM to the negative process-group id, waits the recorded short grace interval, sends KILL to the group if needed, reaps the child, and reports the breached metric and basename. `RLIMIT_AS` is never described as an RSS measurement or RSS cap.
- On macOS, use a parent `ps -o rss=` sampler and the same process-group watchdog for local RSS/time evidence. Record address-space enforcement as unsupported if the platform cannot provide a trustworthy equivalent; do not substitute RSS. Missing or unparsable enforcement is a failed precondition, and Linux CI is the authoritative release gate for all three ceilings.
- For recoverable input, require syntactically valid bounded SVG and exactly the card 02 one-line warning derived only from `disposition == :skipped` diagnostics, with every skipped record's index, canonical type, integer code, and byte offset in physical order. A clean input or an input with only `:preserved_raw` diagnostics emits no skipped-record warning. For unreadable input, require `Emfsvg::ParseError` and no partial SVG. For a resource violation, require `Emfsvg::ResourceLimitError` with its limit metadata and cause intact.
- Run every corrupt/resource subprocess with the manifest-configured production setting, `EMF_BACKEND=auto` plus the pinned `EMF_NATIVE_LIBRARY`, and assert native selection so Ruby fallback cannot mask a native error-contract failure. Reject parser/backend exceptions, panics, signals, and catch-all exception translation.
- Do not modify `lib/emfsvg/dib_decoder.rb` or require direct DIB specs in this issue. If a future pinned corrupt fixture demonstrates a reachable production DIB path, record that fixture and call path in a follow-up before proposing decoder-specific allocation guards.
- Document the recoverable-versus-unreadable policy, calibration schema/commands, platform enforcement differences, and how to add a regression fixture without weakening warning or resource expectations.

## Done when

- The manifest and runtime dependency spec independently verify the corpus, #15 revision, separate diagnostic/resource contract revisions, pinned `emf` runtime, selected production backend, and native artifact; the resilience gate refuses mismatched provenance, and final qualification uses the containing released package.
- The proposed calibration command reproducibly generates and checks `spec/fixtures/resource_limits/emfsvg-v1.yml` from pinned inputs, with separate raw and derived wall-time, peak-RSS, and peak-address-space values plus the exact outer caps and enforcement mechanism.
- Every manifest-listed corrupted file completes under native-selected `EMF_BACKEND=auto` within the committed Linux limits and produces the manifest-selected outcome.
- Every recoverable file returns valid bounded SVG and the exact warning listing only skipped records; clean and preserved-`Raw`-only controls emit no skipped-record warning.
- Every unreadable file raises only `Emfsvg::ParseError` and returns no partial SVG.
- The parent harness terminates and reaps a fixture process group on an RSS or time breach, the child enforces the separate address-space ceiling, and every timeout, resource breach, signal, unexpected exception, or unavailable enforcement capability is attributed to a basename.
- No corrupted case can terminate the test process, consume unbounded resources, or disappear from the inventory.
